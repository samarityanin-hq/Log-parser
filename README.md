# Проект 3. Incident Radar

CLI-утилита для анализа NGINX-логов. Читает логи (файлы, glob-маски или URL),
разбирает строки, фильтрует по датам и строит отчёт со статистикой.

Одна строка лога выглядит так:

```text
93.180.71.3 - - [17/May/2015:08:05:32 +0000] "GET /downloads/product_1 HTTP/1.1" 304 0 "-" "Debian APT-HTTP/1.3"
```

Из неё утилита достаёт IP, дату, метод, ресурс, код ответа и размер ответа.
А из миллиона таких строк собирает картину: сколько запросов, какие endpoint'ы
популярны, сколько ошибок, какие ответы самые тяжёлые.

Здесь впервые появляются «взрослые» требования: файл может быть гигантским
(читаем потоково), строки бывают битыми (пропускаем, а не падаем), а утилиту
будут запускать скрипты (значит, нужны честные коды возврата).

Задание разбито на три merge request'а. Делай их по очереди.

## Быстрый старт

```bash
./gradlew run     # запустить программу
./gradlew check   # тесты и линтеры — ровно то, что проверяет CI
```

Нужен **JDK 25 или новее**. Gradle ставить не нужно — в проекте лежит `gradlew`,
он скачает нужную версию сам.

## Как проверить загрузку логов по HTTP

Для ручной проверки можно раздать готовые сэмплы локальным HTTP-сервером.
Из корня проекта запусти (нужен Python 3):

```bash
python3 -m http.server 8000 --bind 127.0.0.1 --directory samples/logs
```

Оставь этот терминал открытым. По адресу <http://127.0.0.1:8000/> будет список
файлов. В `--path` передавай URL конкретного лога, а не страницы со списком:

```bash
./gradlew run --args='--path http://127.0.0.1:8000/access-2025-03-01.log'
```

Эта проверка имеет смысл после реализации чтения по URL: стартовый шаблон
ещё не обрабатывает аргументы. Остановить HTTP-сервер можно через `Ctrl+C`.

В автоматических тестах сервер должен запускаться и останавливаться самим
тестом, например через Java `HttpServer`. Используй loopback-адрес и порт `0`
(ОС выберет свободный порт), настрой ответы `200` с тестовым логом и `404`,
а в приложение передавай URL с фактическим портом сервера. Останавливай сервер
в `finally` или `@AfterEach`, даже если проверка упала. Тогда тесты смогут
работать в GitLab CI без вручную запущенного сервера и внешних сайтов.

## Быстрый старт

Нужен **JDK 25 или новее**. Gradle ставить не нужно, в проекте есть `gradlew`.

```bash
./gradlew run --args="--path samples/logs/access-2025-03-01.log"
./gradlew check     # тесты, checkstyle, spotless, Error Prone
```

## Параметры

```text
--path, -p             файл, glob-маска или URL (обязателен)
--output-format, -f    json или markdown (по умолчанию json, регистр не важен)
--output-path, -o      путь для отчёта; без него report.json / report.md
--from                 начало периода, yyyy-MM-dd (необязателен)
--to                   конец периода, yyyy-MM-dd (необязателен)
--help, -h             справка
```

Примеры:

```bash
# один файл
./gradlew run --args="-p samples/logs/access-2025-03-01.log"

# glob-маска (кавычки обязательны, иначе маску раскроет оболочка)
./gradlew run --args="-p 'samples/logs/access-*.log'"

# URL
python3 -m http.server 8000 --bind 127.0.0.1 --directory samples/logs
./gradlew run --args="-p http://127.0.0.1:8000/access-2025-03-01.log"
```

## Источники логов

Поддерживаются расширения `.log` и `.txt` (регистр не важен). Любой другой
вход отклоняется ещё до чтения.

- **Локальный файл.** Путь должен указывать на существующий обычный файл,
  каталог или отсутствующий файл дают ошибку использования.
- **Glob-маска.** Маска содержит `*`, `?`, `[` или `{`. Утилита берёт часть
  пути до первого спецсимвола как базовый каталог, обходит его рекурсивно и
  сопоставляет с остатком маски относительные пути (синтаксис glob из
  `java.nio.file`). Подошедшие файлы читаются подряд в алфавитном порядке.
  Обратные слэши в маске приводятся к `/`. Если ничего не найдено, это ошибка
  использования. Учтите правило Java: `dir/**/*.log` не находит файлы
  непосредственно в `dir`.
- **URL.** Схемы `http` и `https`, редиректы поддерживаются, таймаут
  подключения и ожидания ответа 10 секунд. Ответ читается потоком, на чтение
  тела таймаут не распространяется.

Во всех случаях файл не загружается в память целиком: строки идут через
`BufferedReader.lines()`. Некорректные байты UTF-8 заменяются, а не роняют
чтение.

## Коды возврата

| Код | Когда |
|---|---|
| `0` | успех |
| `1` | непредвиденная ошибка: сбой чтения во время обработки, недоступный сервер, ответ 5xx |
| `2` | некорректное использование |

К коду `2` относятся: нет `--path`, неизвестная опция, неверный
`--output-format`, неверная дата, `--from >= --to`, неподдерживаемое
расширение входа, расширение отчёта не соответствует формату, файл не найден
или это не файл, маска ничего не нашла, некорректный URL, ответ 4xx (в том
числе 404), превышено время ожидания ответа.

Сообщения об ошибках выводятся в `stderr`, логи тоже уходят в `stderr`.
`stdout` оставлен под отчёт.

## Принятые решения

- **Ошибка пользователя и сбой программы разделены.** Любое нарушение
  инвариантов входных данных это `2` (брошенный `UsageException`), а всё,
  что произошло уже при работе с корректным вводом, это `1`.
- **Сервер ответил 4xx** считается ошибкой пользователя (неверный URL),
  **5xx и обрыв соединения** считаются сбоем (`1`).
- **Проверки идут от дешёвых к дорогим:** разбор источника и формата,
  расширение отчёта, границы дат, и только потом открытие файла или сети.
  Поэтому `--from >= --to` сообщается даже если файл не существует.
- **Источник это sealed-интерфейс** (`LocalFile`, `Glob`, `Remote`), что
  делает выбор читателя исчерпывающим `switch` без `instanceof`.
